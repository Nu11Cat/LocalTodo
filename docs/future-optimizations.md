# LocalTodo 后续优化建议

本文记录 LocalTodo 在完成当前 MVP 能力后的后续优化方向，主要面向产品体验、数据安全、AI 协作和工程维护。

## 当前状态

LocalTodo 目前已经具备一个本地优先开发任务工具的基础闭环：

- 本地桌面应用基础框架。
- 结构化任务模型。
- 任务筛选和项目聚合。
- AI Context 复制与导出。
- JSON 导入导出。
- 通过 Electron main/preload 保存到应用数据文件。
- 按项目导出 `.localtodo/` 工作区，包括项目上下文、任务 JSON 和每任务 Markdown。
- `.gitignore` 提示和生成能力。

下一阶段不建议直接跳到 SQLite、MCP、本地 HTTP API 或自动执行命令。更稳妥的方向是先补齐用户数据保护、任务体验和 AI Context 控制能力。

## 优先级建议

### P0：敏感任务保护

目标：避免个人任务、内部信息或敏感上下文被默认导出给 AI 工具或提交到仓库。

建议能力：

- 给任务增加 `sensitive` 或 `private` 标记。
- 在任务详情面板中提供开关。
- AI Context 复制和导出默认排除敏感任务。
- 导出时显示被排除的敏感任务数量。
- 提供显式选项：允许用户本次导出包含敏感任务。
- JSON 兼容旧数据，旧任务默认 `sensitive: false`。

验收重点：

- 默认导出的 AI Context 不包含敏感任务标题、描述、文件路径和命令。
- 用户明确选择后才允许包含敏感任务。
- 旧数据迁移后不会丢任务。

### P0：导入覆盖前的安全提示和恢复点

目标：降低用户误导入导致当前任务被覆盖的风险。

建议能力：

- 导入 JSON 前提示“导入会替换当前任务”。
- 在导入前自动生成一次当前数据备份。
- 导入失败时保留当前任务不变。
- 导入成功后显示导入任务数量。

验收重点：

- 用户不会在无提示情况下覆盖当前任务。
- 导入无效 JSON 不会改变现有数据。
- 导入前备份可用于人工恢复。

### P1：项目绑定体验优化

目标：让用户更容易把任务绑定到真实代码仓库。

建议能力：

- 在任务详情中提供“选择项目目录”按钮。
- 支持从项目面板批量为任务设置仓库路径。
- 自动识别同一项目下已有任务的仓库路径，并作为建议值。
- 对不存在或非绝对路径的仓库路径给出提示。

验收重点：

- 用户不需要手动复制长路径也能绑定仓库。
- 同一项目的任务更容易保持一致的 `projectName` 和 `repoPath`。
- Renderer 仍然不直接访问 Node 文件系统，目录选择通过 preload/main 完成。

### P1：`.localtodo/` 导出增量与清理

目标：让项目工作区导出更稳定，避免旧任务 Markdown 残留造成 AI 读取过期上下文。

建议能力：

- 导出时检测 `.localtodo/tasks/` 中由 LocalTodo 生成但当前项目已不存在的旧任务文件。
- 删除旧文件前必须提示用户确认。
- 或先实现“列出将清理文件”的预览模式。
- 在 `AI_CONTEXT.md` 中记录生成时间、任务数量和来源说明。

验收重点：

- 默认不静默删除文件。
- 用户确认后才清理 stale task Markdown。
- 导出结果不会混入已删除任务的旧上下文。

### P1：任务备注和进展记录

目标：把任务从静态待办扩展为轻量开发日志。

建议能力：

- 为任务增加 notes 或 activity log。
- 支持追加进展记录，而不是只编辑描述。
- AI Context 中按时间展示任务进展。
- 支持记录“阻塞原因”“下一步动作”。

验收重点：

- 用户能追踪任务为什么停滞、最近做了什么。
- AI 可以从上下文中理解任务历史，而不仅是当前标题。

### P1：任务模板

目标：减少重复录入，提高任务质量。

建议能力：

- 提供常用模板，例如 Bug、Feature、Refactor、Release。
- 模板预填类型、描述结构、验证命令和标签。
- 支持项目级默认命令。

验收重点：

- 新建任务更快。
- AI Context 更结构化，包含稳定的目标、验收和验证信息。

### P2：搜索和筛选增强

目标：提升任务数量变多后的查找效率。

建议能力：

- 保存常用筛选视图。
- 支持按更新时间、创建时间、优先级排序。
- 增加“最近更新”“阻塞中”“无项目绑定”等快捷视图。
- 支持标签多选逻辑说明，例如任意匹配或全部匹配。

验收重点：

- 任务数量增加后仍能快速定位。
- 用户能发现缺少项目、缺少描述或长期未更新的任务。

### P2：数据文件可观测性

目标：让用户知道数据保存在哪里，以及保存是否正常。

建议能力：

- 设置页展示当前数据文件路径。
- 提供“打开数据目录”按钮。
- 显示最近保存时间。
- 保存失败时提供更明显的 UI 提示，而不是只写入控制台。

验收重点：

- 用户可以定位自己的数据文件。
- 保存失败不会静默发生。

### P2：文档和上手体验

目标：降低新用户理解成本。

建议能力：

- 在 README 中增加用户指南入口。
- 补充截图或简单使用流程图。
- 增加“第一次使用”章节。
- 增加“如何配合 Claude Code 使用”的专门文档。

验收重点：

- 用户不用阅读开发文档也能开始使用。
- AI Context 和 `.localtodo/` 的用途更容易理解。

## 暂缓方向

以下方向有价值，但建议等任务模型和 AI Context 体验稳定后再做：

### SQLite

适合在任务量、查询能力、事件日志或多实体关系明显复杂后引入。当前 JSON 文件更简单、可读、可迁移。

### MCP Server

适合在数据模型、权限边界和命令语义稳定后再暴露给外部 AI 工具。过早做 MCP 会增加接口维护成本。

### 本地 HTTP API

需要处理端口、安全、鉴权、跨应用访问和生命周期管理，建议晚于 CLI 或 MCP 评估。

### 自动执行命令

涉及权限、安全、终端输出、失败恢复和用户确认。建议先只记录命令，不自动执行。

### AI 自动删除任务

删除是破坏性操作，应排在追加备注、更新状态、生成建议之后。

## 推荐下一步

建议下一个开发任务优先做：

**敏感任务保护：给任务增加敏感标记，并让 AI Context 默认排除敏感任务。**

原因：

- 与当前 AI Context 和 `.localtodo/` 导出能力直接相关。
- 能补齐现有验收重点中的数据安全要求。
- 改动范围可控，主要涉及任务模型、详情 UI、导出过滤和测试。
- 在继续扩展 AI 能力前，先建立默认安全边界。
