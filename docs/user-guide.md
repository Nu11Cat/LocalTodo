# LocalTodo 用户使用说明

LocalTodo 是一个本地优先的桌面任务管理应用，适合开发者在自己的电脑上记录任务、整理项目上下文，并把任务信息导出给 Claude Code、Cursor 等项目内 AI 工具使用。

## 适合谁使用

LocalTodo 适合希望把开发任务保存在本地、并和代码项目上下文关联起来的用户，尤其适合：

- 记录日常开发待办、Bug、功能需求和技术债。
- 按项目查看任务进度。
- 为 AI 编程工具准备结构化上下文。
- 在不依赖云服务的情况下备份和迁移任务数据。

## 核心特点

- **本地优先**：任务数据保存在本机，不依赖在线账号或远程服务。
- **结构化任务**：每个任务可设置状态、优先级、类型、标签、描述、项目、仓库路径、相关文件、命令和敏感标记。
- **项目视图**：可按项目聚合任务，查看某个项目下的任务集合。
- **敏感任务保护**：敏感任务默认不会进入 AI Context 和 `.localtodo/` 导出，只有明确确认后才会包含。
- **`.localtodo/` 工作区导出**：可在项目目录下生成 AI 可读取的任务上下文文件。
- **JSON 导入导出**：支持备份、迁移和恢复任务数据。

## 启动应用

开发环境中可以在项目根目录运行：

```bash
npm run dev
```

如果默认端口被占用，开发服务会自动尝试其他端口。Electron 窗口启动后即可使用应用。

构建正式版本可以运行：

```bash
npm run build
```

构建产物会输出到 `out/` 目录。

## 基本使用

### 新建任务

1. 在顶部输入框填写任务标题。
2. 点击 **Add** 或按回车创建任务。
3. 新任务会出现在 **Active** 列表中。

### 编辑任务详情

在任务列表中点击 **Edit**，可以编辑任务的详细信息，包括：

- 状态：例如 active、done。
- 优先级：用于区分任务紧急程度。
- 类型：例如 feature、bug、chore 等。
- 标签：用于按主题或模块分类。
- 描述：记录任务背景、验收标准或补充说明。
- 项目名称：用于归类到项目面板。
- 仓库路径：用于 `.localtodo/` 项目导出。可以点击 **Browse…**（选择目录）按钮通过系统目录选择器直接选定本机仓库目录，无需手动粘贴长路径。
  - 如果同一项目名称下的其他任务已经填写过仓库路径，应用会显示一个一键采用的建议路径。
  - 如果填写的仓库路径不是绝对路径，应用会在输入框下方给出提示。
- 相关文件：记录任务涉及的代码文件。
- 命令：记录验证、构建或排查命令。
- 敏感标记：用于标记不希望默认导出给 AI 工具的个人、内部或敏感任务。

### 敏感任务

任务详情中可以勾选敏感标记。敏感任务仍会保存在本地并正常显示、编辑和筛选，但默认不会包含在以下输出中：

- 活跃任务 AI Context。
- 项目级 AI Context。
- `.localtodo/` 工作区导出的 `AI_CONTEXT.md`、`tasks.json` 和每任务 Markdown。

当你直接复制单个敏感任务，或导出时选择包含敏感任务，应用会要求本次操作明确确认。

### 完成或恢复任务

点击任务前的复选框可以切换任务状态。

- 未完成任务显示在 **Active** 区域。
- 已完成任务显示在 **Completed** 区域。

### 删除任务

点击任务右侧的 **Remove** 可以删除任务。

> 删除任务是本地数据变更，操作前请确认任务不再需要。需要备份时可以先导出 JSON。

### 清理已完成任务

当存在已完成任务时，可以点击 **Clear completed** 清理完成列表。

## 查找和筛选任务

应用提供筛选栏，可以按以下条件查找任务：

- 关键词：搜索标题、描述或标签。
- 状态。
- 优先级。
- 类型。
- 标签。
- 项目。

当存在筛选条件时，列表会显示当前筛选结果数量。点击 **Clear filters** 可以清空所有筛选。

## 项目视图

当任务填写了项目名称或仓库路径后，应用会显示项目面板。

项目面板可以帮助你：

- 查看每个项目下有多少任务。
- 快速筛选某个项目的任务。
- 复制某个项目的 AI 上下文。
- 导出某个项目的 AI 上下文文件。
- 导出项目 `.localtodo/` 工作区。

建议为同一个代码仓库下的任务填写一致的：

- 项目名称。
- 仓库路径。

这样项目聚合和导出结果会更准确。

## AI Context 使用方式

LocalTodo 可以把任务整理成 Markdown，方便交给 AI 编程工具理解当前工作。敏感任务默认会被排除；如果本次操作需要包含敏感任务，应用会要求你明确确认。

### 复制单个任务上下文

在任务列表中点击 **Copy AI Context**，会复制该任务的 Markdown 上下文。

适合在和 AI 讨论单个任务时使用。

### 复制活跃任务上下文

点击 **Copy active context**，会复制当前活跃任务的整体上下文。

适合让 AI 了解当前还未完成的工作。

### 复制项目上下文

点击 **Copy project context**，会复制所有任务组成的项目级上下文。

如果在项目面板中操作，则可以复制某个项目分组的上下文。

### 导出项目上下文文件

点击 **Export project context** 可以把 Markdown 上下文保存为文件，默认文件名为：

```text
AI_CONTEXT.md
```

如果任务中绑定了同一个仓库路径，应用会优先建议导出到该仓库的 `.localtodo/AI_CONTEXT.md`。

## `.localtodo/` 工作区导出

当项目任务填写了仓库路径后，可以在项目面板中导出 `.localtodo/` 工作区。

导出后会在对应仓库下生成：

```text
.localtodo/
  AI_CONTEXT.md
  tasks.json
  tasks/
    task_<id>.md
```

文件说明：

- `AI_CONTEXT.md`：项目级 AI 上下文。
- `tasks.json`：该项目任务的结构化 JSON 数据。
- `tasks/task_<id>.md`：每个任务对应的 Markdown 上下文。

这些文件可以让 Claude Code、Cursor 等项目内 AI 工具更容易读取当前项目任务背景。默认导出时，敏感任务不会写入这些文件；只有你在本次导出中明确选择包含敏感任务时才会写入。

### 清理过期任务文件

当你删除了任务、修改了任务的项目名称，或本次导出排除了敏感任务后，`.localtodo/tasks/` 中可能残留由 LocalTodo 之前生成、但当前项目已不再包含的 `task_<id>.md` 文件。这些过期文件会让 AI 读到已删除任务的旧上下文。

每次导出后，应用会检测这类过期文件，并列出文件名询问是否删除：

- 选择确认后，应用只删除匹配 `task_<id>.md` 命名的过期文件，并报告删除数量。
- 选择取消则全部保留。
- 清理只针对 LocalTodo 自己生成的任务文件，你手动放入 `.localtodo/tasks/` 的其它文件不会被删除。

应用默认不会静默删除任何文件。

### `.gitignore` 提示

导出 `.localtodo/` 工作区时，应用会询问是否把生成文件加入项目的 `.gitignore`。

推荐忽略以下内容：

```gitignore
.localtodo/tasks.json
.localtodo/AI_CONTEXT.md
.localtodo/tasks/
```

选择确认后，应用会把缺失条目追加到仓库 `.gitignore`，并避免重复添加。

选择取消时，导出仍会继续，但应用会提醒你手动处理 `.gitignore`。

> 如果任务内容包含个人计划、内部信息或敏感上下文，建议不要把 `.localtodo/` 生成文件提交到公开仓库。

## JSON 备份和迁移

### 导出 JSON

点击 **Export JSON** 可以下载当前任务数据，默认文件名为：

```text
localtodo-export.json
```

适合用于：

- 手动备份。
- 迁移到另一台电脑。
- 在修改大量任务前保留恢复点。

### 导入 JSON

点击 **Import JSON** 选择之前导出的 JSON 文件。

导入会替换当前任务列表。替换前，LocalTodo 会先解析文件并显示当前任务数量和导入文件中的任务数量，确认后才会继续。

确认导入后，应用会先在本地数据目录创建当前任务的 JSON 恢复点；只有恢复点创建成功后，才会用导入文件中的任务替换当前任务。

如果 JSON 文件无效、读取失败，或恢复点创建失败，当前任务不会被覆盖。导入成功后，应用会显示恢复点文件路径。

## 数据保存位置

LocalTodo 会优先通过 Electron 主进程把数据保存到应用数据目录中的 `data.json`。

旧版本或浏览器式环境下可能使用 `localStorage`。应用会在可用时尝试把旧数据迁移到本地应用数据文件。

如果保存的数据文件无法读取，应用会提示错误，并避免用空数据覆盖已有文件。

## 建议工作流

一个推荐的日常使用方式：

1. 为每个开发任务创建一条 LocalTodo 任务。
2. 在任务详情中补充项目名称、仓库路径、相关文件和验证命令。
3. 开发前复制单个任务 AI Context，让 AI 理解任务目标。
4. 项目任务较多时，使用项目面板筛选和导出上下文。
5. 需要让项目内 AI 工具读取任务背景时，导出 `.localtodo/` 工作区。
6. 定期使用 **Export JSON** 备份任务数据。

## 注意事项

- LocalTodo 当前是本地桌面应用，不提供云同步。
- `.localtodo/` 文件可能包含个人任务信息，提交到 Git 前请检查内容。
- JSON 导入会替换当前任务列表，导入前建议先备份。
- 任务里的仓库路径需要是本机存在的项目路径，才能正确导出 `.localtodo/` 工作区。
- AI Context 是辅助信息，不会自动执行命令或修改代码。
